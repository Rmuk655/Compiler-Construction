# Q3 - Summary of the paper

Paper: "Efficiently Computing Static Single Assignment Form and the Control Dependence Graph" by Cytron, Ferrante, Rosen, Wegman and Zadeck (ACM TOPLAS, 1991)

1. The paper is about building SSA form and the control dependence graph (CDG) efficiently. Both were already known to be useful for optimisations, but people didn't use them much because they thought building them would be slow and the result could get very large. The authors give algorithms that work for any control flow graph.

2. In SSA each variable is assigned once, and phi functions are added where control flow merges. One advantage they mention is def-use chains: with D definitions and U uses of a variable there can be D*U chains, but in SSA there are at most E (the number of edges in the CFG).

3. The main problem is deciding where to put the phi functions. Putting a phi for every variable at every join point works, but it adds a lot of useless phis. They want minimal SSA, where a phi is only added where two different definitions of a variable meet. They also mention pruned SSA, which leaves out phis for variables that are not used later.

4. To do this they introduce dominance frontiers. DF(X) is the set of nodes Y such that X dominates a predecessor of Y but does not strictly dominate Y. So it is basically the boundary where X stops dominating. A definition in X can meet a different definition at these nodes, so that is where phis are needed.

5. Computing DF directly from the definition would take quadratic time. Instead they go bottom up over the dominator tree and build DF(X) from DF_local(X), which comes from X's successors in the CFG, and DF_up from each child of X in the dominator tree. This is linear in the size of the DF sets.

6. Phi placement: for a variable V, take all nodes that assign to V and put phis in their dominance frontiers. A phi is also an assignment to V, so the nodes where phis were added have to be processed too. This gives the iterated dominance frontier DF+. They use a worklist with two flags per node (HasAlready and Work) so that each node is processed only once per variable.

7. Renaming: after the phis are placed, variables are renamed by walking the dominator tree from the top. A stack is kept for each variable. At a definition a new version is pushed, uses get the version on top of the stack, phi operands in successor blocks are filled in, and when we leave a block its versions are popped.

8. The same idea also gives control dependence. Y is control dependent on X if X is a branch that decides whether Y runs or not. They show that control dependences are just the dominance frontiers of the reverse CFG (post dominance frontiers), so the same algorithm can build the CDG.

9. Translating out of SSA: machines don't have phi instructions, so each phi is replaced by copies at the end of each predecessor block. Doing only this leaves a lot of extra copies, but they say that dead code elimination before and storage allocation by colouring after removes most of them. They also explain how arrays and structures are handled, using Access and Update operations, where an Update makes a new version of the whole array.

10. Complexity: in the worst case the DF sets can be O(n^2) in total (for example with nested repeat-until loops), and converting to SSA can be O(n^3). For programs with only if-then-else and while loops they prove each DF has at most 2 nodes, so there it is linear. They also tested it on 221 FORTRAN procedures (from EISPACK, FLO52 and SPICE). The size of the DF sets, the number of phis and the size of the CDG all grew roughly linearly with program size. For 95% of the procedures there were less than 2.3 phis per statement.

What I got from this paper is that even though the worst case looks bad, SSA is cheap to build in practice, which is probably why almost every compiler uses it now. LLVM's mem2reg also uses iterated dominance frontiers to place phi nodes.
