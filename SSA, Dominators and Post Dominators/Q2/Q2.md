# Q2 - Static Single Assignment

SSA (Static Single Assignment) is a form of the IR where every variable is assigned only once. If a variable is assigned more than once in the code, the compiler splits it into versions like x1, x2, x3 and changes each use to the version that reaches it.

For example:

```
x = 1          x1 = 1
x = x + 2      x2 = x1 + 2
y = x * 3      y1 = x2 * 3
```

This is easy for straight line code. The problem comes with branches. After an if-else we don't know which version of x we have, because it depends on which branch ran. SSA handles this by adding a phi function at the point where the branches join:

```
if (c) x1 = 4
else   x2 = 6
x3 = phi(x1, x2)
```

phi here means "take x1 if we came from the if branch, and x2 if we came from the else branch". Real machines don't have a phi instruction, so before code generation the compiler replaces the phis with normal copies.

The main point is that every variable now has only one place where it is defined. So when we see a use of a variable we directly know where its value came from. Without SSA we would have to run reaching definitions analysis to find that out.

## Which optimisations benefit from SSA

1. Constant propagation - if x1 = 5 then every use of x1 is 5, since x1 is never assigned again. SCCP (sparse conditional constant propagation) works on SSA and can also remove branches that can never be taken.

2. Dead code elimination - if a variable has no uses, its definition can be deleted. In SSA this is easy to check because each name has one definition and a list of its uses.

3. Copy propagation - for y1 = x1 we can replace y1 with x1 everywhere, because neither of them changes later.

4. Common subexpression elimination / GVN - if a1 + b1 is computed twice it has to be the same value both times, since a1 and b1 can't change. So the second one can just reuse the first. This works across basic blocks and not only inside one block.

5. Loop optimisations - a loop counter shows up as a phi at the loop header (like i2 = phi(0, i3) and i3 = i2 + 1), so induction variables are easy to find for strength reduction. For loop invariant code motion, if the operands of an instruction are not defined inside the loop (and it has no side effects), it can be moved out of the loop.

6. Register allocation - live ranges in SSA are simpler, and the interference graph of an SSA program is chordal, so it can be coloured optimally in polynomial time.

Def-use chains also get much smaller in general. A variable with D definitions and U uses can have D*U chains, but in SSA every use has exactly one definition.

Because of this, most compilers today (LLVM, GCC) do most of their optimisations on SSA form. In LLVM, the mem2reg pass converts local variables into SSA early on so that the later passes can use it.
